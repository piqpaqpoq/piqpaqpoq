# 픽팩폭 RSS 수집 준비

## 현재 상태
- 기존 Sites 웹사이트의 최신 소스 스냅샷을 저장소에 함께 이전했습니다. 호스팅은 기존 Sites를 유지합니다.
- 저장소의 기존 README는 변경하지 않았습니다.
- 예약 실행, 자동 배포, 유료 AI API는 연결하지 않았습니다.
- 기존 공개 사이트는 이 저장소를 읽지 않습니다. 수집 결과를 사이트에 전달하는 단계도 남아 있습니다.
- 2026.11.17: 로컬 테스트 6개, 사이트 빌드·Worker 검증 통과. 첫 RSS 수집 15/15개 성공, 기사 329건 저장. 결과 파일의 checkedAt이 실제 수집 시각입니다.

## 수집 범위
사용자가 제공한 Google 뉴스 검색식을 바탕으로 15개 RSS를 구성했습니다.
편의점 1그룹, 카페 2그룹, 베이커리 1그룹, 디저트·도넛 1그룹에서 각각
신제품·신메뉴 / 할인·쿠폰·증정 / 협업·굿즈·팝업을 수집합니다.

- 기사 제목, 게시일, 매체명, 링크, 업종·주제만 저장합니다.
- 최근 7일 기사이며 상품 출시일이나 행사 유효기간을 보장하지 않습니다.
- 기사 링크와 정규화한 제목의 정확한 중복을 합칩니다. 비슷한 사건의 다른 제목까지 합치는 의미 분석은 아닙니다.
- 같은 기사에 여러 주제가 있으면 태그를 합칩니다.
- 퍅미 도메인·매체명·제목은 제외하며 해당 사이트를 요청하지 않습니다.
- 기사 본문, 이미지, X·Threads 게시물은 수집하지 않습니다.
- 모든 피드가 실패하면 기존 파일을 덮어쓰지 않고 실패 처리합니다.
- 일부 실패 시 기존 7일 내 자료를 유지하고 피드별 성공·실패를 기록합니다.
- Google 뉴스의 결과 제한·검색 누락·접속 차단 가능성이 있습니다.

## 수동 실행
GitHub 저장소 → Actions → ‘RSS 수집 · 수동 실행’ → Run workflow
1. 먼저 mode=check로 테스트합니다.
2. 성공 후 mode=collect로 첫 실제 수집을 합니다.
3. 결과는 비공개 저장소의 data/rss-news.json에 저장합니다.
4. 실행 자체가 Actions 포함 사용량을 사용하며 무료라고 보장하지 않습니다.
로컬에서 테스트와 첫 수집은 완료했습니다. GitHub Actions 자체 실행 이력은 별도로 확인해야 합니다.

## 실행 제한
- 테스트 작업: 최대 2분.
- 수집·저장 작업: 최대 5분.
- 동시 실행 금지, 재시도 없음.
- 외부 Python 패키지 설치 없음. Python 표준 라이브러리만 사용합니다.
- Actions artifact 업로드 없음. 저장소에 텍스트 결과 파일 하나만 저장합니다.
- 작업 타임아웃은 월간 과금 차단 설정을 대신하지 않습니다.

## 예약 실행 전 확인할 사항
- Billing에서 실제 플랜·남은 포함 사용량 확인.
- 초과 사용 중단과 사용량 알림 설정 확인.
- check 및 collect 성공과 실제 소요 시간 확인.
- 사이트 원본 코드 이전, 호스팅/저장소 연결, 운영자 인증 확인.
- 그 뒤 하루 3회 예약을 추가합니다. 예상 시각은 한국시간 07:17 / 13:17 / 19:17입니다.
  아직 확정·설정되지 않았습니다. Actions 예약은 지연될 수 있습니다.

## 보안
저장소를 Private으로 유지하세요.
인증 토큰, .env, 방문자 식별값, 문의 내용, 사용자 데이터는 커밋하지 않습니다.
자격 증명은 필요한 단계에서 GitHub Secrets에 넣으며 수집기는 현재 자격 증명을 요구하지 않습니다.

## 전체 사이트 이전에 남은 것
page.html, Worker 서버 코드, 원본 캐릭터/로고, 빌드 스크립트와 설정의 소스 스냅샷은 이전했습니다.
방문자 집계와 공식 행사 스냅샷 등 서버 저장 데이터는 소스 코드와 별도입니다.
브라우저에 저장한 기록은 GitHub로 자동 이전되지 않습니다.
기존 호스팅을 그대로 유지하므로 서버 저장 데이터는 원래 저장소에 남아 있습니다. 새 호스팅으로 전환할 때 별도 이전이 필요합니다.
